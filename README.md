# CC98 AI+

CC98 论坛的浏览器插件（Chrome / Edge），两个功能：

- **AI 搜索** — 输入一个话题，自动拆关键词 → 搜帖 → 读楼层回复 → 生成带来源引用的总结。全程在你自己电脑上跑，用你自己的 CC98 登录态和 AI API Key。
- **订阅提醒** — 订阅感兴趣的关键词，有新帖命中就通过钉钉或邮箱推送给你。这部分需要连后端。

只想用 AI 搜索的话，**跳过后端相关的全部内容**，配好第一节就能用。

---

# 一、给使用者

## 1. 安装插件

1. Chrome 地址栏输入 `chrome://extensions`
2. 右上角打开「**开发者模式**」
3. 点「**加载已解压的扩展程序**」，选中 `cc98-ai-plus` 这个文件夹（是文件夹本身，不是里面的 src）

装好后打开 `https://www.cc98.org` 并登录，右下角会出现 🤖 按钮。

> **看不到 🤖？** 装插件前就开着的页面不会自动注入，按 `F5` 刷新一下。

## 2. 配置 AI

点击插件图标 → **设置**（也可以右键插件图标 → **选项**）。



你需要一个 AI 服务商的 API Key。设置页先选择服务商，插件会自动填写推荐的 API 地址和模型：

| 服务商 | Base URL | 模型填 | 说明 |
|---|---|---|---|
| **DeepSeek** | `https://api.deepseek.com` | `deepseek-chat` | 便宜、效果好，**推荐** |
| **硅基流动** | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-14B-Instruct` | 注册送额度 |
| **智谱 AI** | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | 该模型免费 |
| **阿里百炼** | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 有免费额度 |

拿 Key 的地方一般在服务商后台的「API 密钥」页面，生成一串 `sk-` 开头的字符串。

1. 粘贴 API Key；需要时可以修改模型名称
2. 点「**测试当前填写**」确认连接可用
3. 点同一卡片里的「**保存 AI 配置**」

测试始终使用当前输入框内容，但不会自动保存；有未保存修改时，页面会直接提示。

> **第一次用非默认服务商（DeepSeek / 智谱 / 阿里百炼）时，点「测试连接」或「保存」会弹一次浏览器授权框**，问你「允许访问 xxx 吗」，点「允许」即可。因为插件默认只放行了 CC98 和硅基流动，其他服务商按需授权，只弹这一次。

## 3. 用 AI 搜索

点右下角 （或按 `Ctrl+Shift+K`）→「 搜索」→ 输入话题 → 回车。

进度条会依次走过：拆分关键词 → 搜索 CC98 → 筛选主题 → 阅读回复 → 生成总结。

**一次搜索大约要 1～2 分钟**，因为 CC98 接口有 1.2 秒的限速，还要逐个读帖子的回复。进度条在动就是正常的，耐心等。

结果包含：用了哪些关键词、Markdown 格式的总结、以及带编号的来源帖子链接（可点开原帖）。



设置页的「搜索预算」控制挖多深，默认是拆 4 个关键词 → 每词搜 20 条 → 选 10 个帖子 → 每帖读 30 楼。

- **快**：把「选取主题数」降到 5、「每主题最多读回复」降到 15
- **全**：反过来调大，但会更慢更费 token

## 4. 校外访问（WebVPN / RVPN）

**不用做任何设置，插件自动适配。**

- 走 **RVPN / ZJU-Connect** 直连 `https://www.cc98.org` → 正常工作
- 走 **WebVPN**（`webvpn.zju.edu.cn/https/...`）→ 插件自动把接口地址转换成 WebVPN 的编码路径，搜索结果里的帖子链接也会指向 WebVPN

技术细节见「四、实现说明」。

## 5. 订阅提醒

**这部分需要后端在运行**

### 登录

-> 设置 → 填你的**浙大邮箱**（`@zju.edu.cn`）→ 发送验证码 → 收信 → 填 6 位码 → 验证登录。

### 添加订阅

→ 订阅 → 填写一个订阅表达式。输入时会实时显示解析结果；语法不合法时不能提交。



匹配发生在新帖的标题和正文中。表达式只有两种运算符：**空格表示“且”**，半角 **`/` 表示“或”**；其他相连字符都按原样作为完整关键词，包括 `C++`、`C#`、`.NET` 和标点。

| 写法 | 结果 |
|---|---|
| `后端 实习` | 标题或正文必须同时包含“后端”和“实习” |
| `后端/服务端 实习` | 必须包含“实习”，并包含“后端”或“服务端”之一 |
| `C++ 校招` | `C++` 会作为完整关键词，不会被拆成 `C` |

每个关键词至少 2 个字符且不能只由标点组成；`/` 两侧不能为空，只接受半角 `/`；规范化后总长最多 255 个字符。

一个账号最多存在 **10 个**订阅，暂停的订阅也计数。达到上限后仍可暂停、恢复或删除；只有删除才能腾出新建名额。

### 通知设置

→  设置 → 选**通知间隔**，配**钉钉**或**邮箱**渠道。

**间隔是「攒一批发」的意思**：后端固定每 10 分钟扫一次新帖，命中的先攒着，到你选的间隔（比如 1 小时）再把这段时间攒下的合并。

**钉钉**：
1. 钉钉里建个群（只有自己也行）→ 群设置 → 智能群助手 → 添加机器人 → **自定义**
2. 安全设置勾「**加签**」，复制 Webhook 地址和 `SEC` 开头的密钥
3. 填进设置页 → 点**保存并启用**。之后可以直接用「启用 / 停用」切换状态，无需再次保存；也可以先点「发送测试（不保存）」验证当前填写

**邮箱**：填你要接收的邮箱地址即可，发信服务器由部署方统一配置。

### 通知列表

→ 通知。能看到命中的帖子和**为什么命中**。通知列表只读取后端已经生成的结果，不会触发全站扫描。

插件不在后台轮询通知。打开通知页时会读取一次，60 秒内再次打开或刷新会直接使用本机缓存。未读位置也只保存在当前浏览器中；首次读取建立基线。

如果最近一次钉钉或邮箱投递失败，通知页和设置页会显示渠道错误。失败批次不会自动补发，但帖子仍会保留在通知列表中。

# 三、常见问题

**右下角没有 图标**
装插件前就开着的页面不会注入，`F5` 刷新。改过插件代码的话，要先在 `chrome://extensions` 点 🔄 重新加载，再刷新页面。

**「CC98 登录凭证无效或已过期」**
CC98 的登录态一小时过期。刷新 CC98 页面即可，页面会自动续期。

**「LLM 服务拒绝了这个 API Key」**
Key 和 Base URL 不配套。官方 Key 要配官方地址，中转站的 Key 要配中转站地址。展开「技术详情」能看到服务商返回的原话。

**「模型输出不完整」**
适当调小「选取主题数」或「每主题最多读回复」，也可以换用输出能力更稳定的模型。

**搜索很慢**
正常，CC98 接口限速 1.2 秒。想快就调小「选取主题数」和「每主题最多读回复」。

**订阅了但收不到通知**
先看实时解析结果是否符合预期：空格是“且”，`/` 是“或”。也确认后端在线、订阅状态为“启用”，并检查通知渠道是否显示最近发送失败。

**遇到别的错误**
错误框里展开「技术详情」，那里有服务器返回的原始内容。插件的日志在 `F12` → Console，搜 `[CC98 AI+]`。

# 四、实现说明

## 目录结构

```
cc98-ai-plus/
├── manifest.json                    # MV3 配置
├── vendor/marked.esm.js             # Markdown 渲染，本地打包不走 CDN
└── src/
    ├── shared/constants.js          # 全局常量
    ├── background/service-worker.js # 网络代理 + 工具栏徽章同步（不轮询通知）
    ├── content/
    │   ├── index.js                 # 内容脚本入口（动态 import 加载）
    │   ├── main.js                  # 初始化 UI + 快捷键
    │   ├── lib/                     # storage / net / errors / cc98-api / llm-client
    │   │                            # token-extractor / webvpn / auth / backend-api
    │   ├── pipeline/                # 搜索管线：keyword→search→filter→read→summarize
    │   └── ui/                      # 悬浮按钮 / 面板 / 进度条 / 各 Tab
    └── pages/
        ├── popup/                   # 工具栏弹窗
        └── options/                 # 设置页
```

## 安全边界

- **所有网络请求都经后台 Service Worker 转发**，绕过浏览器 CORS——CC98 和各家 LLM 接口都不放行浏览器跨域。
- **CC98 登录态**存在 `chrome.storage.session`（内存，关浏览器即清空），只发给 `api.cc98.org`。
- **LLM API Key** 存在 `chrome.storage.local`，只发给你自己填的 Base URL。
- **两者都不会给后端**。后端只做订阅扫描和通知，用它自己的 CC98 账号，用你的浙大邮箱作用户标识。
- 转发请求默认 **不携带 cookie**（`credentials: 'omit'`），避免把站点凭证泄露给 LLM 服务商；只有 WebVPN 请求例外，因为它靠 cookie 维持会话。
- 论坛内容会用 `<forum_content>` 标签包裹后再交给 LLM，降低提示词注入风险。

## WebVPN 适配

WebVPN（深信服方案）把主机名用 **AES-128-CFB** 加密进路径，key 和 IV 都是 `wrdvpnisthebest!`，最终路径为 `hex(IV) + hex(密文)`。

- 网页链接：直接复用当前地址里已经编码好的前缀
- 接口地址：现算 `api.cc98.org` 的编码路径（带缓存）

WebCrypto 不支持 CFB 模式，所以用「零 IV 的单块 AES-CBC」凑出原始块加密原语，再手工实现 CFB 反馈链，已与 OpenSSL 逐位比对一致。

WebVPN 域名下挂着全校站点，插件只在编码段确实对应 `cc98.org` 时才注入界面，不会在教务网等页面冒出悬浮按钮。

## 已知限制

- 通知未读位置和最近一次成功列表都保存在本机；清除插件数据或换浏览器后会重新建立基线。
- 钉钉 Webhook 和 Secret 不会由后端回传。修改已保存渠道或发送测试时，需要重新粘贴完整凭据。
